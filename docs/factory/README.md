# Grainworks Factory Agent

가상 사료공정의 생산 상태·품질 영향·설비 정지 조건을 읽고 설명하는 개인 프로젝트. 실제 우성 공장이나 MES의 복제·운영·개선 실적이 아니다.

## 공개 인재상과 프로젝트의 연결

공식 채용 보도는 주도·집요·융합·향상을 제시한다. 이 프로젝트의 대응은 지원 전략상의 해석이다. 분리된 기록을 연결하는 문제 가정은 주도, 실패 기록·회귀 검사와 재실행은 집요, 공정 데이터·화면·로컬 LLM 연결은 융합, 기존 물류 화면을 생산 중심으로 개선한 과정은 향상에 대응한다. 이 기능들이 회사 내부 프로젝트의 요구사항이거나 본인 단독 개발 성과라는 뜻은 아니다.

## 시연 사건

`fixtures/factory-state.json`은 기존 엔진에서 합성 수분 이상을 발생시킨 데이터다. RAW-2401의 15.8% 기록과 시연 기준14%를 연결한다. 미출하 LOT-001 4,800kg + LOT-003 3,600kg = 보류8,400kg. 기출하 LOT-009 4,000kg은 영향 확인으로 분리한다. 합성 기록과 가정이며 실제 사료 검사 기준·현장 조사 결과가 아니다.

공정 화면과 인수인계·장부 대조는 같은 저장 Lot 상태를 읽는다. 새 설비 용량 비교는 해당 상태의 복사본을 읽는 **별도 모델**이다. 기존 화면의 단순 단계 시간 진행을 설비 제약 기반 시뮬레이션으로 바꾸었다고 설명하지 않는다.

## 두 시간 모델의 구분

가정한 사용자는 생산·품질 담당자다. 배합 설비가 10분 멈췄을 때 20분 뒤 포장 완료 물량과 대기 상태가 어떻게 달라지는지 비교하고, 품질 보류를 유지한 채 재검사 검토 대상을 판단한다. 핵심 결과 지표는 비교 시간 내 포장 완료 kg이다. 이 사용자의 업무와 요구는 공개 사례에서 정한 시연 가정이며 현장 인터뷰로 확인한 내용은 아니다.

- `engine.js`: 기존 공정 단계 시간, 검사·보류·수동 해제·출하 기록. 화면 재생을 담당.
- `factory_model.js`: 설비별 한 Lot씩 처리하는 FIFO 용량 모델. 초기 진행률과 가정 용량을 반영하며, 포장 완료 시 창고에 적재한다. 품질 보류·기출하 Lot은 유지하고 신규 입고·손실·수율·납기·출하 일정은 계산하지 않는다.
- MIX-01 10분 정지 / 20분 비교: 정상15,200kg vs 정지10,000kg의 포장 완료. 60분 비교에서는 양쪽19,400kg로 같아진다. 이 차이는 합성 조건 계산이며 실제 성과나 최적화율이 아니다.
- 포장 로봇과 벨트의 움직임은 처리 가능한 포장 Lot의 진행률에 따른 설명용 표현이다. 실제 관절·장비 제어 모델이 아니다. 일시정지·보류·차단·설비 중단·동작 감소 설정에서 멈춘다.

## 실제 AI 증거와 한계

`live-status.json`, `live-downtime.json`, `live-quality.json`은 실제 로컬 Qwen 호출과 도구 결과·근거를 보존한다. API는 운영 상태를 변경하는 도구를 제공하지 않는다. 정지 시간·비교 시간·설비 ID를 입력에 명시하고 모델이 도구 값을 바꾸면 거부한다.

AI 서술 전체를 검증했다고 표시하지 않는다. 실제 다중 Lot 요약에서 기출하 LOT-009를 미출하 보류로 잘못 설명한 사례도 있었다. `history/quality-summary-semantic-failure.json`에 원문을 보존했으며 요약 단계의 입력에도 출하 여부·물량·미출하 보류와 기출하 영향 합계를 명시했다. 원본 도구 데이터가 맞더라도 자유 서술의 의미가 맞는지는 별도로 확인해야 한다.

원인을 정확하게 설명했지만 요청한 두 물량을 요약에서 빠뜨린 응답은 `history/quality-summary-incomplete.json`에 보존했다. 두 문장의 역할을 원인 설명과 물량·검토 상태로 나눠 필수 답변 범위를 지정했다. 합계에 단일 Lot ID를 붙여 개별 물량처럼 설명한 응답은 `history/quality-summary-attribution-failure.json`에 보존하고 집계 범위 표현을 보완했다.

 설비 조회 요약에서 보류 물량을 ‘보유량’으로 표현한 사례, 첫 정지 비교에서 응답 길이 한도로 서술을 보류한 사례가 있었다. 새 작업의 요약 입력을 줄이고 길이 한도를 조정해 재실행했다. 정확한 값·상태는 도구 카드와 원본 근거로 확인한다.

다중 Lot 조회에서는 로컬 모델 문맥 한도 오류가 발생해 실패 기록을 `history/quality-context-failure.json`에 보존했다. 모델에 보내는 도구 메시지만 필요한 기록으로 줄였으며 원본 API·근거·활동 이력은 유지했다. 재시도에서는도구 선택 출력이225토큰 한도에 도달한 뒤 실패했다. 다중 Lot 출하 검토에만768토큰을 부여했으며4096문맥과 단일 Lot의225토큰 입력 조건은 유지했다. 오류 문구도 Ollama JSON의 짧은 문자열만 보존하도록 했다.

이후 모델이 미확인 근거 ID `TOTAL-shippedImpactKg`로 기출하 Lot 조치를 제안해 도구가 거부했다. 요청이 LOT-003의 재검사 초안만 요구했는데 모든 조회 대상의 조치를 요구하던 조건을 고쳤다. 세 Lot 조회는 유지하고 명시한003의 `resolve`만 제안 조건으로 요구하며 범위 밖 제안은 거부한다. `history/quality-bounded-retry.json`은 수정 전 실제 실패다. 기존 모델 평가12건/수정 재검증과 이번 세 가지 시연을 하나의 정확도 수치로 합산하지 않는다.

비교 시간이 설비 완료 시각과 정확히 같을 때 다른 설비의 진행률이 누락되는 오류도 수정했다. 포장1,000kg이 1분에 완료되고 배합1,200kg이 함께 시작하면, 배합 진행률은0.5여야 한다는 회귀 검사를 추가했다.

## 참고 표현과 기여

[MicroFactory 참고 영상](https://x.com/ihorbeaver/status/2107210345051988131)의 공정 셀·컨베이어·단계 설명 표현을 참고했다. 영상은 로봇 조립·자가 복제 공장 구상이며 우성의 공장이 아니다. 외부 영상·3D 모델을 복사하지 않고 Three.js로 독자적인 사료공정 형상을 구성했다. 일반 사료 공정의 상세 확장에는 [ANDRITZ 공식 공정 자료](https://www.andritz.com/feed-and-biofuel-en/industries/animal-feed)를 참고할 수 있으나 우성이 해당 설비를 사용한다는 근거로 쓰지 않는다.

김현태: 지원 방향·공장 중심 화면·자연어 질의·근거 확인·사람 조치 요구, 가독성 피드백. Codex: 설계·구현·자동 검사·실행 검증·문서 제작. 김현태의 직접 코딩·현장 요구 분석·실제 효율 개선으로 확대하지 않는다.
