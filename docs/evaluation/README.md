## 별도의 결정적 검사

[검사 기록](deterministic-checks.json): 엔진 16 + 현장 대상 5 + 상태 서버 6 + Agent 백엔드 25 + HTTP 4 + 실제 문서 추출 8 = **64개 통과**. 모의 모델 전송은 API·도구 가드 검사이며 LLM 정확도 근거로 합산하지 않습니다. 문서 8개는 실제 PDF 문자 추출과 RapidOCR 경로를 포함합니다. 기본 OCR의 한글 푸터 누락은 [문서 추출 한계](../../DOCUMENT_INTAKE.md)에 기록했습니다.

## 실제 발견한 실패와 수정

- CSV 매핑에서 모델이 수량 컬럼 `weight_kg`를 단위 컬럼으로 지정해 **4500을 단위로 해석**했습니다. 검증 도구가 이를 거부했습니다. 단위를 추정해서 채우지 않고 native schema에 `unitMode`(column/fixed)와 `unitSource`를 필수로 분리한 뒤 동일 실제 모델 사례를 다시 실행했습니다.
- 문서에서 숫자 대신 `"12.0 %"`를 보냈거나 원문 12.0 대신 장부 11.9를 제시한 결과를 거부했습니다. 수치형 필드와 문자열 필드의 schema를 나누고 정확한 원문 구절을 필수로 받습니다. 누락 온도는 채우지 않습니다.
- 전체 12개 시험에서는 문서에 있는 `Lot ID`를 모델이 빠뜨렸고, 가정 부족 질문에 도구 호출 없이 바로 답해 Agent 실행이 실패했습니다. 영어 데모 라벨로 명시된 원문 필드가 추출에서 빠지면 자동 보완 대신 거부·재요청하고, 가정이 없어도 먼저 저장된 Lot을 조회하도록 도구 선택 지시를 보강했습니다. 원문에 없는 수분·온도는 새로 만들거나 시뮬레이션에 투입하지 않습니다. 이 두 사례는 위의 최신 소스 재시험 기록으로 구분합니다.
- 올바른 도구 결과가 있어도 이전 UI의 AI 문장은 정상 수분을 보류 원인이라고 쓰거나 시뮬레이션 가정을 잘못 해석했습니다. 작업별 요약 입력 범위를 좁혔고 잘린 모델 응답은 설명 보류로 표시합니다. 전체 의미 검증을 완료했다고 주장하지 않습니다.
- 최종 조건 비교 UI에서도 자유 서술이 **전체 출하량을 LOT-007 자체의 배출량으로 표현**하고 온도 25°C를 `2과`로 잘못 적었습니다. 실제 계산 카드와 원본 도구 결과는 40,000kg/44,500kg, 가정 25°C로 정확했습니다. 숫자 집합·ID 가드만으로 수량의 대상이나 오타 전체를 막을 수 없다는 남은 실패입니다. 해당 [실제 UI 결과](ui-simulation-final.json)를 보존했으며, 모델 설명을 자동 조치·검증된 사실로 사용하지 않습니다. 필드별 의미 일치와 문장 품질 평가는 다음 단계입니다.
- AI가 제시한 조치 사유가 재검사를 이미 했다는 표현을 포함할 수 있었습니다. 모델 사유는 미검증 초안으로 분리하고 수동 조치 창에는 저장 근거를 확인하라는 도구 문구만 전달합니다. 실제 재검사·해제는 사람이 수행합니다.
