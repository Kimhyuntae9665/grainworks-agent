# 우성 IT/AX 생산·품질·주문 RAG 포트폴리오 · v13

[최신 3페이지 PDF](portfolio.pdf) · [3쪽 미리보기](preview-100-page-3.png) · [편집 소스](build_orders_portfolio.py) · [PDF 검수](pdf-qa.json)

공고의 데이터·AI 기반 업무를 위해, 생산·주문 기록과 SOP를 연결해 답변의 값·출처를 대조하는 기능을 만들었습니다. 합성 데이터와 모의 SOP를 사용하는 개인 프로토타입이며 실제 우성 시스템 연동이나 현장 성과가 아닙니다.

| 요청 | 반영 페이지·파일 | 결과 |

1쪽은 공장·주문·검사 패널을 같은 화면에서 확인하는 기존 캡처를 유지했습니다. LG AX 교육 중 평택 공장의 디지털 트윈을 견학해 제조 시뮬레이션에 관심을 가졌다는 사용자 확인 경험을 짧은 캡션에 반영했습니다. 견학 날짜·설비명·실제 구축 경력으로 확대하지 않았습니다.

2쪽은 SO-001의 미출하 보류 8,400kg / 기출하 영향 4,000kg / 미배정 600kg을 구분하고 배정 변경 결과를 유지했습니다. 기출하 영향은 출하 이력의 부분 집합으로, 보류 물량에 다시 더하지 않습니다.

3쪽은 기존 큰 로고 나열 대신 **실제 검증 표를 중심**으로 구성했습니다. [원본 화면](../rag/ui-normal.jpg)의 표 부분만 PDF에서 확대했으며 원본 JPG의 UI·값·출처는 수정하지 않았습니다. [실행 JSON](../rag/ui-normal-live.json)과 [고정 비교 JSON](../evaluation/rag-live.json)에 대응합니다. RAG와 SOP의 뜻은 캡션에서 풀어 설명합니다.

## 09·19를 적용한 범위

[UI reference kit](https://github.com/Kimhyuntae9665/ui-reference-kit)의 09는 같은 조건의 결과를 나란히 비교하는 원칙입니다. RAG 끔/켬의 질문과 상태 해시를 대조했습니다. 사용 전에는 실제 Qwen 응답 후 보류, 사용 후에는 6개 항목의 값·출처 대조 통과였다는 제한된 사례입니다. 검색 기능 도입에 따른 일반 정확도나 속도 개선율로 표현하지 않았습니다.

19는 구성 요소와 근거를 분리해 설명하는 원칙입니다. 장식적인 입체 분해도 대신 코드·AI·사람의 책임을 평면 흐름으로 나눴습니다. ID 기록 조회는 코드가 수행하고, EmbeddingGemma는 문서 검색에 사용됩니다. Qwen3 4B/Ollama가 답변 항목을 생성하며 Python 검증이 LangGraph 흐름에서 값·자료형·출처를 대조합니다. 원문 확인과 재검사·해제는 사람이 수행합니다. 참고 제품 이미지를 프로젝트 실행 화면으로 사용하지 않았습니다.

## 검증과 한계

- 합성 5시나리오 × RAG 끔/켬 = 10건의 정의한 검사 통과. 실제 모델 호출 6회, 코드 사전 차단 4건을 구분합니다.
- 정상 GUI의 6항목: 기준 14%, 재검사 필요, 별도 해제 필요, LOT-003 수분 15.8%, SO-001 보류 8,400kg·기출하 영향 4,000kg입니다.
- 구조화 항목의 값·출처를 검사한 결과입니다. 자유 서술 전체·임의 질문의 이해·실제 품질·근본 원인을 보장하지 않습니다.
- 모델이 근거를 읽지 못하고 보류한 실패 기록도 [검수 문서](../rag/verification.md)에 보존합니다.
- ERP/MES/PLC·n8n 연동, 회사 내부 요구 조사, 실측 개선 성과는 없습니다.
- 본인: 공장·주문 통합 방향, 근거 확인 기능 제안과 화면 검토. Codex: 구현·자동 검사·실행 검증 지원.

공식 직무 근거는 [우성 IT/AX 공고](https://woosung.recruiter.co.kr/career/jobs/128746)의 ‘사내 시스템·인프라 운영 및 데이터·AI 기반 업무’입니다. 기존 보존한 공식 공고 이미지와 문구를 대조했습니다. 이번 재열람에서는 공식 페이지 제목만 추출되어 상세 문구의 현재 게시 상태나 마감일을 새로 확인한 것으로 표시하지 않습니다. [우성 공개 MES 사례](https://www.woosungfeed.co.kr/m11.php)는 프로젝트 착안 자료이며 내부 요구를 확인한 근거는 아닙니다.

## 재생성과 문서 검수

Windows 맑은 고딕, ReportLab·Pillow·PyMuPDF·qrcode가 필요합니다. 포트폴리오 작성 의존성은 앱 실행 의존성과 구분합니다.

```powershell
.venv/Scripts/python.exe -X utf8 docs/portfolio/build_orders_portfolio.py
```

빌더는 버전 PDF·최신 별칭 `portfolio.pdf`, 전체·100% 미리보기, 링크·본문 경계·글꼴·테두리 좌표 검수 JSON을 생성합니다. 생성 직후의 육안 검수 상태는 `pending`이며 최종 렌더링을 확인한 뒤 기록합니다.

v13은 3페이지를 전체·100% 보기로 확인했습니다. 1쪽의 기존 화면 범위, 2쪽 숫자·선 경로, 3쪽 표의 6행·출처·얇은 영역 표시·설명선·역할 흐름, 각 스크린샷의 바깥 네 변, 본문/캡션/푸터 분리와 QR 링크를 확인했습니다. PDF 본문은 최소 11pt이며 캡처 내부 글자는 원본 이미지의 확대 크기에 따릅니다. 원본 캡처와 RAG 평가 소스 13개의 해시를 대조했습니다. 앱 코드 변경 없이 기록된 실제 실행 증거를 사용했으므로 새 모델 호출이나 전체 앱 테스트를 반복하지 않았습니다.

새 서술은 `i-am-not-ai`의 report/light 경로로 진단·원문 대조·서법 복원·쉼표 정리·게이트 검사를 실행했습니다. 최종 변경률 2.70%, 게이트 exit 0, 수치 누락·서법 소실 0건입니다. 긴 검증 문장은 작은 영역에서 읽기 쉽도록 원래의 짧은 문구로 복원한 뒤 재검사했습니다. 실행 기록은 작업 폴더 `work/i-am-not-ai/2026-10-10-rag-v13`에 있고, 제출 본문에는 메타 블록을 넣지 않았습니다.
