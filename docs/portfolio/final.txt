[cover.title]
출하를 막는 기록을 AI가 찾고 사람이 조치를 결정합니다.

[cover.subtitle]
제조 기록 조회와 검토 초안을 돕는 AX 실습입니다. Lot(생산 묶음)을 읽는 로컬 LLM Agent와 3D 화면을 연결했습니다.

[cover.problem_title]
AX 목적: 조회·대조·초안 작성 지원

[cover.problem]
검사값과 배정 기록을 수작업으로 따라가야 한다고 가정했습니다. AI가 보류 근거와 영향 트럭을 조회하고 사람이 조치를 결정합니다. 현장 인터뷰로 확인한 불편은 아닙니다.

[cover.inspiration]
우성의 MES 입고→출고 흐름과 데이터·AI 업무 혁신 방향에 착안했습니다. 가상 Lot·트럭을 연결했습니다. 3D에서는 대상과 위치를 함께 확인하도록 했으며 탐색 시간 단축은 미측정입니다.

[cover.human]
김현태: 자연어 출하 조회, 검사값·기준·경보 ID 근거 설명, 이력 초안을 요청했습니다. 해제는 사람이 수행하도록 범위를 정하고 화면·상태·그래픽 개선을 요구했습니다.

[cover.codex]
Codex: 데이터 규칙·화면·AI Agent 구현, 실행 검증·자동 평가와 공개 저장소 구성을 수행했습니다.

[cover.model]
실제 오픈소스 LLM: Qwen3 4B · Ollama CPU · LangGraph

[cover.boundary]
가상 검사값과 모의 배정을 사용했습니다. 실제 우성 시스템을 수정하거나 운영한 경험은 아닙니다.

[flow.title]
LOT-007의 보류 근거를 찾고 조치는 사람이 승인합니다.

[flow.subtitle]
LOT-007 4,500kg은 검사 온도 31°C가 시연 기준 28°C를 넘어 보류됩니다. LOT-008 3,200kg은 정상 상태입니다.

[flow.relation_note]
창고 7,700kg은 두 Lot을 포함합니다. 배정 트럭의 상태는 연결된 Lot에서 반영하며 같은 재고를 다시 합산하지 않습니다.

[flow.ai_title]
질문: 지금 출하를 막는 문제와 영향받는 트럭은?

[flow.ai_caption]
LLM이 조회 도구를 선택해 기록을 읽고 설명 초안을 씁니다. 수량 계산과 식별자·근거 정리는 검증 도구가 담당합니다.

[flow.proposal_title]
사람에게 남긴 조치 결정

[flow.proposal_caption]
AI의 제안을 확인한 사람이 사유를 입력하고 조치를 결정합니다. AI는 품질 보류를 직접 해제하지 않습니다.

[flow.boundary]
근거가 확인된 도구 결과와 AI가 작성한 미검증 서술을 구분해 표시합니다. 시연 기준은 실제 SOP·HACCP 기준이 아닙니다.

[validation.title]
AI의 파일 대조와 조건 비교를 근거로 검토합니다.

[validation.reconcile]
단위를 맞춰 Lot 수량을 대조합니다. t와 kg의 동등한 수량을 구분하고 4,700kg처럼 원본과 다른 값은 불일치로 표시합니다.

[validation.document]
PDF 텍스트 추출과 RapidOCR 결과를 원문과 나란히 확인합니다. 추출된 문장을 곧바로 품질 판정으로 취급하지 않습니다.

[validation.simulation]
60분 분기 시뮬레이션에서 기본 40,000kg과 조치 분기 44,500kg을 비교합니다. 비교 중 원본 상태는 유지합니다.

[validation.architecture]
3D 화면·운영 데스크 → Python API → LangGraph 읽기 전용 도구 → 상태 기록·SQLite

[validation.limit]
현재 한계: 가상 데이터와 로컬 모델로 확인했습니다. 실제 ERP 연동, 회사 배포, 업무 효율 개선은 검증하지 않았습니다.
